# 10. Localized information

**Maya** should be able to recognize a university or verifier in her preferred language. Localized metadata lets the publisher provide language-specific names and other permitted information. [Federation §14](https://openid.net/specs/openid-federation-1_0.html#section-14).

Publish localized fields through host metadata or the appropriate protocol role. Shared core language helpers validate syntax when editing; the application chooses a display language after obtaining the relevant information.

## Present information in the reader’s language

A university can publish a base display name and language-tagged alternatives. LIGO Wiki preserves those claims while validating the entity, then chooses an appropriate presentation for Maya. Another application can choose a different language without changing the underlying federation identity.

Keep language selection in the display layer. Entity Identifiers, claim names, signatures, and protocol comparisons still follow their own exact rules. A translated label must not become a substitute lookup key for an entity or a policy parameter.

When building an editor, show which localized field the operator is editing and retain alternatives the UI is not currently displaying. Validate tag syntax where the contract requires it, escape external text, and offer an understandable fallback when the preferred language is absent. The application chooses that fallback; the library does not invent translated values.

## Work through this topic

Keep language-tagged fields intact and apply the documented selection rules. Display information remains untrusted content for HTML rendering.
