# 6.7. Check whether a subject is currently listed for a mark type

[Feature guides](README.md) / [6. Trust Marks](6.trust-marks.md) · [Example context](6.trust-marks.md#example-context)

**Maya's wallet** can ask which entities currently qualify for a mark type, then look for **Car Rental Company** locally.

## Choose what to disclose

The auditor's Authority class exposes `listTrustMarkedEntities()` for local administrative use. **Maya's wallet** calls a remote issuer, so it uses core's `fetchTrustMarkList()` client; there is no Wallet role method for that HTTP request. Both query an existing accreditation decision and do not issue a mark. [Marked entities listing](https://openid.net/specs/openid-federation-1_0.html#section-8.5); [Privacy](https://openid.net/specs/openid-federation-1_0.html#section-19.2).

```ts
import type { TrustAnchor, Intermediate } from "@oidfed/authority";
import { fetchTrustMarkList } from "@oidfed/core";

export function listAtIssuer(auditor: TrustAnchor | Intermediate) {
  return auditor.listTrustMarkedEntities("https://licence-federation.example/marks/approved-verifier");
}

export function listedVerifier() {
  return fetchTrustMarkList("https://auditor.example/list", {
    trustMarkType: "https://licence-federation.example/marks/approved-verifier",
  });
}
// Check result.ok, then look for the subject in result.value locally.
```

Omitting `sub` follows the privacy mitigation described in §19.2. Pass `{ trustMarkType: type, sub: subjectId }` for a smaller filtered response when disclosing the subject is acceptable. Both are standard Listing requests. Endpoint metadata must come from trusted issuer evidence.

The issuer applies full current eligibility before deduplicating subjects. An expired replacement does not hide an older eligible mark; a subject remains listed while at least one qualifying mark exists. Membership does not prove that a particular previously received JWT is active.

Client options support endpoint authentication and additional request parameters. Server extensions can constrain understood parameters; unknown parameters remain ignored. Storage failures cannot become successful partial lists.

## Choose the query before sending it

To test one subject directly, send the optional `sub` selector. To avoid telling the issuer which holder interests **Maya's wallet**, request the list for `trust_mark_type` only and test membership locally. The latter can transfer a larger list, so account for response limits and the federation's listing policy.

The answer concerns current membership for a type, not the validity of every JWT a holder might present. Keep signature validation and any exact-JWT status requirement separate. Do not interpret an unreachable endpoint as a positive membership result; decide whether the current operation can wait or must stop.
