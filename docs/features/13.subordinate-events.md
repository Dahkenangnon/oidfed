# 13. Subordinate Events

[Feature guides](README.md)

An enrollment, update, or withdrawal at **eduGAIN** can leave signed event history. Operators can retrieve that history to understand what changed. [Extension: Draft 01](https://openid.net/specs/openid-federation-subordinate-events-1_0-01.html).

Use the Authority's enrollment, update, revocation, and `recordSubordinateEvents()` methods to create history. `getSubordinateEvents()` reads it locally; the advertised endpoint serves signed history to remote clients.

## Turn history into a bounded refresh signal

When Umeå joins, changes keys, or leaves, eduGAIN can record events alongside the authoritative lifecycle update. A consumer retrieves the signed history for the subject and tracks the point it has processed. This lets it notice changes before an ordinary scheduled refresh.

The consumer still decides what the change means for its own application. A key-update event can trigger fresh evidence retrieval; it is not itself a replacement key set to trust without validation. An enrollment change may require reevaluating registrations, while existing sessions remain an application responsibility.

Make event processing repeatable. Save progress only after successful handling, tolerate retries, and keep storage transactions consistent with the lifecycle operations that create events. If the deployment configures response expiry, callers must also honor that signed lifetime rather than treating a history response as permanently fresh.

## Subordinate Events, Draft 01

The endpoint is optional for Trust Anchors and Intermediates under [§2.1](https://openid.net/specs/openid-federation-subordinate-events-1_0-01.html#section-2.1). [§2.1.1](https://openid.net/specs/openid-federation-subordinate-events-1_0-01.html#section-2.1.1) defines how to advertise it in metadata, and [§2.3.1](https://openid.net/specs/openid-federation-subordinate-events-1_0-01.html#section-2.3.1) specifies a history JWT signed with a Federation Entity Key.

When event storage is enabled, oidfed's [lifecycle methods](../../packages/authority/src/subordinate-lifecycle.ts) capture registration, changes to attested metadata and policies, registered key changes, and explicit revocation. Production adapters commit each mutation and its generated events together under the [event storage contract](11.6.storage-adapters.md#subordinate-events).

Direct writes to `storage.subordinates` bypass automatic capture. Under the [capture contract](11.6.storage-adapters.md#subordinate-events), applications must append events in the same transaction if those changes belong in the published history. Enabling storage does not reconstruct past events from timestamps.

oidfed requires history to survive removal and prohibits silent pruning or truncation. The draft's [response format](https://openid.net/specs/openid-federation-subordinate-events-1_0-01.html#section-2.3) defines event data but prescribes no retention duration, database, or transaction mechanism.

[§2.3.3](https://openid.net/specs/openid-federation-subordinate-events-1_0-01.html#section-2.3.3) defines `suspension` as a suspended registration and `revocation` as a revoked registration. Custom event types `MAY` be defined and `SHOULD` be documented by the framework or operator. The operator defines the administrative process behind these events; their names already have specification-defined meanings.

oidfed's [`recordSubordinateEvents()`](../../packages/authority/src/subordinate-lifecycle.ts) records observations without changing registration state. Your application enforces suspension. `revokeSubordinate()` removes the current registration and records revocation. Record revocation only when removal reflects that decision; technical cleanup alone does not.

The response reports the issuer's view of events under [§2.3.1](https://openid.net/specs/openid-federation-subordinate-events-1_0-01.html#section-2.3.1). Its signature alone does not prove that the chain-validation checks in [Federation §10.2](https://openid.net/specs/openid-federation-1_0.html#section-10.2) passed at an earlier time. The draft defines a retrieval endpoint and provides no notification protocol. See [subordinate event history](13.1.subordinate-events.md#lifecycle-recording-and-endpoint-responses) for oidfed's capture boundaries and lookup policies.
