# 9.2. Withdraw a subordinate registration

[Feature guides](README.md) / [9. Updates, rollover, and revocation](9.updates-and-keys.md) · [Example context](9.updates-and-keys.md#example-context)

A service leaves **Umeå University**. The operator removes its current registration and records why it is no longer being endorsed.

## How to use it

`revokeSubordinate()` operates on the authority's registration, not the participant's private keys or every cached JWT. When event storage is configured, lifecycle recording and registration removal share the transaction. [Revocation](https://openid.net/specs/openid-federation-1_0.html#section-11.4); [Subordinate Events Draft 01](https://openid.net/specs/openid-federation-subordinate-events-1_0-01.html#section-2.3.3).

```ts
import { entityId } from "@oidfed/core";
import type { TrustAnchor, Intermediate } from "@oidfed/authority";

export async function withdrawUmeaOp(authority: TrustAnchor | Intermediate) {
  await authority.revokeSubordinate(entityId("https://op.umu.example"), {
    eventDescription: "Participation agreement ended",
  });
}
```

## What your application owns

Decide when withdrawal should occur and how applications react before old evidence expires. The example's event annotation requires event-enabled storage; omit the annotation if that capability is not configured. There is no automatic broadcast to all consumers. Applications query the Subordinate Events endpoint to obtain changes. Even a later chain refresh can succeed using an unexpired cached Subordinate Statement; withdrawal does not erase that evidence. Event history records the issuer's view; it does not prove what every remote consumer accepted. A suspension event alone does not remove a registration: applications must implement the corresponding enforcement policy.

## Understand what withdrawal can stop

Removing Umeå from Umeå University's subordinate records stops future positive statements from that authority's active enrollment state. It does not delete signed statements already held by peers. Consumers learn the change through refresh and any additional federation-defined process.

Decide what your application does with active sessions and registered clients after withdrawal. Federation does not define a universal revocation protocol for all such artifacts. If your federation uses Subordinate Events, consume them as a signal to reassess state; verify the evidence relevant to the resulting decision.
