# 7.2. List an authority’s immediate subordinates

[Feature guides](README.md) / [7. Federation endpoints](7.federation-endpoints.md) · [Example context](7.federation-endpoints.md#example-context)

**Research Portal** needs candidate OP identifiers for a sign-in selector. **Umeå University** can list its immediate subordinates without asking the portal to inspect every registration record.

## How to use it

The Authority's `listSubordinates()` reads its own immediate registrations with the requested filters. Advertise `federation_list_endpoint` and route requests through `handleRequest()` to expose the same listing over HTTP. A remote directory consumer uses core's `fetchListSubordinates()`; it does not need to construct a second Authority to contact the first. [Listing](https://openid.net/specs/openid-federation-1_0.html#section-8.2).

```ts
import type { TrustAnchor, Intermediate } from "@oidfed/authority";

export function universityCandidates(umu: TrustAnchor | Intermediate) {
  return umu.listSubordinates({ entityTypes: ["openid_provider"], intermediate: false });
}
export function serveUniversity(umu: TrustAnchor | Intermediate) {
  return (request: Request) => umu.handleRequest(request);
}
```

## Query another authority

<!-- oidfed-example -->
```ts
import type { CryptoEngine } from "@oidfed/crypto";
import { fetchListSubordinates } from "@oidfed/core";

export function remoteUniversityCandidates(engine: CryptoEngine) {
  return fetchListSubordinates("https://umu.example/list", {
    entityType: "openid_provider", intermediate: false,
  }, { engine });
}
```

The remote client returns a `Result`; local `listSubordinates()` returns the identifiers or rejects its promise on failure. In either case the identifiers are candidates, not validated participant metadata.

## What your application owns

Basic listing covers immediate registrations, not an entire federation graph. Do not turn inclusion into an authorization decision. The authority's storage adapter must implement the documented filtering semantics, including validity checks for Trust Mark filters. Use Extended Listing for pagination and selected statement information, or Entity Collection for a broader informational directory.

## Use listing as discovery input

LIGO Wiki can use a subordinate list to find participants to investigate. Inclusion means the authority lists the identifier; it is not a completed trust decision about that entity's effective metadata or accreditation.

Follow listed entities through the normal discovery and validation path with the application's own anchors and budgets. A federation crawl may encounter multiple authorities with different authentication requirements. Use the per-responder authentication provider when credentials must vary, and avoid treating the root authority's assertion as valid for every descendant.
