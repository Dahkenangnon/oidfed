# 7.1. Serve and retrieve Subordinate Statements

[Feature guides](README.md) / [7. Federation endpoints](7.federation-endpoints.md) · [Example context](7.federation-endpoints.md#example-context)

**LIGO Wiki** follows **Umeå University OP**'s authority hint to **Umeå University**. It needs the statement **Umeå University** issued about **Umeå University OP**, not merely the authority's own EC.

## How to use it

Publish `federation_fetch_endpoint` in the authority metadata and register the subordinate. The authority signs Fetch responses on demand by default. Use `getSubordinateStatement()` to issue one in process, and Core's `fetchSubordinateStatement()` to retrieve one as a client. [Fetch endpoint](https://openid.net/specs/openid-federation-1_0.html#section-8.1).

```ts
import { entityId } from "@oidfed/core";
import type { TrustAnchor, Intermediate } from "@oidfed/authority";

export async function umeaOpStatement(authority: TrustAnchor | Intermediate) {
  return authority.getSubordinateStatement(entityId("https://op.umu.example"));
}
export function serveAuthority(authority: TrustAnchor | Intermediate) {
  return (request: Request) => authority.handleRequest(request);
}
```

## Serve approved retained statements

Set `loadSubordinateStatement` on a Trust Anchor or Intermediate to serve an existing JWT from the active approved publication. The loader receives the current record as an immutable snapshot and a signal for cancellation. It can return a JWT or `undefined`. Supply `crypto.readPublishedFederationJwks` from the authority's current publication so that verification works while signing custody is unavailable.

```ts
import { TrustAnchor, type AuthorityConfig } from "@oidfed/authority";

export function createRetainedAuthority(
  config: AuthorityConfig,
  readApproved: NonNullable<AuthorityConfig["loadSubordinateStatement"]>,
) {
  return TrustAnchor.create({
    ...config,
    subordinateLifetime: (record) => record.isIntermediate ? undefined : 2700,
    loadSubordinateStatement: readApproved,
  });
}
```

`subordinateLifetime` is independent of the loader. It selects a positive safe-integer lifetime for newly issued statements. Returning `undefined` uses the host default. A renewal worker can call `getSubordinateStatement()` and activate its output after approval.

Fetch and Extended Listing verify the saved JWT against the currently published Federation keys, the current algorithm policy, and the approved subordinate record. Extended Listing returns the saved JWT only when selected and takes statement claims such as `iat`, `exp`, and `metadata_policy` from that JWT. The registration audit timestamps keep their usual meaning. Fetch returns `404` for a removed or unknown subject. A request that needs unavailable, expired, or invalid retained evidence returns `503 temporarily_unavailable`. [Extended Listing Draft 03 §3.3](https://openid.net/specs/openid-federation-extended-listing-1_0.html#section-3.3)

The application selects the active approved generation, including after a removal and re-registration with identical claims. Share that generation and its artifacts across replicas to serve identical bytes. Choose a renewal margin, stop yielding withdrawn artifacts, and apply any publication fence needed during cutover. The loader may withhold a JWT before expiry if a relying workflow needs more usable time. Keep storage bounds, expiry cleanup, and audit retention in the application. During issuer key rollover, the old JWT remains eligible while its key is still published and permitted. Activate replacement evidence before removing the old key from the live set.

If an included row needs unavailable retained evidence, Extended Listing returns `503` for that page. Rows beyond the page boundary remain reachable through the next cursor. Optional Authority logs report a fixed reason code for retained evidence failures.

## What your application owns

Keep the advertised URL and the mounted route consistent, including any fixed query parameters. Authenticate requests if the federation requires it. The response still needs issuer, subject, time, and signature checks in its chain context. Fetching a JWT and decoding its payload is not chain validation. Only the host's administrative interface should alter enrollment records.

Pass `authentication` to `fetchSubordinateStatement()` when **Umeå University** requires it. The client sends an authenticated form POST and checks the audience against `issuer` when supplied. Without authentication it uses GET. A fixed selector in the advertised URL cannot be replaced with a conflicting value. The response must use HTTP `200`.

## Check the authority and subject

Umeå University's Fetch endpoint issues a Subordinate Statement for the requested subordinate. Its response should be evaluated as evidence from that authority about that subject. Successful transport does not make a statement from a different issuer or for a different subject interchangeable.

The public Entity Configuration endpoint remains a separate discovery operation. Configure authentication only for endpoints whose policy calls for it. If Fetch authentication fails, correct the method, client keys, or responder audience; do not retry anonymously when the federation requires authentication.
